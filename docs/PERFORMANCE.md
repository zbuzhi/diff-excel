# 1 万行 × 20 列性能测试

测试日期：2026-10-16。环境：Apple M3 Pro、36 GiB 内存、macOS arm64。
使用 Rust `release` 构建，默认保留新文件格式、添加旧内容批注、高亮差异。

## 样本与方法

- 每份工作簿 1 张工作表，1 万行（含 1 行表头）、20 列。
- 每份 190,001 个有内容单元格，含 9,999 条乘法公式，以及中文文本、数字、布尔值、空白和基础样式。
- XLSX 压缩文件每份约 1.14 MiB。压缩体积不能代表加载后的内存需求。
- 少量变化场景：500 处文本、200 处数值、100 处公式修改、100 处清空、100 处填入。200 处数值修改另引起 200 处公式缓存结果变化，因此预期共 1,200 处差异。
- 大量变化场景：9,999 处客户名称修改，覆盖预览 5,000 条上限。
- 各场景顺序启动 3 个独立进程，耗时取中位数，峰值内存取 3 次最大值。未清除操作系统文件缓存，不能视为冷盘测试。
- 测量不含生成样本、编译和结果校验。`process_wall_s` 含进程启动、读取、对比、Excel/日志导出及退出清理，不含 GUI 初始化和绘制。

## 结果

| 场景 | 差异数量 | 进程总耗时中位数 | 进程峰值内存最大值 |
| --- | ---: | ---: | ---: |
| 完全相同 | 0 | 1.19 秒 | 376.9 MiB |
| 少量变化 | 1,200 | 1.20 秒 | 378.0 MiB |
| 大量变化 | 9,999 | 1.24 秒 | 387.7 MiB |
| 大量变化，关闭批注 | 9,999 | 1.23 秒 | 378.6 MiB |

大量变化、默认设置场景中，两个工作簿读取合计约 0.47 秒，对比与报告导出约 0.51 秒，其中 Excel 保存阶段约 0.29 秒。这些阶段计时不含进程退出时对象释放，不能与进程总耗时直接等同。

在这个规模上速度足够快，内存约 0.4 GiB，仍有优化空间。关闭批注降低约 9 MiB 峰值内存，这组测试不足以证明显著的耗时改善。没有测量 Go 版本，不能据此声称 Rust 比 Go 快。不能用这组结果推断复杂图表、图片、百万行、多工作表或其他电脑的表现。

## 准确性检查

用独立的 Python ZIP/XML 读取器核对原始值、类型及公式，得到预期变化坐标和分类，再与完整差异日志逐项比对。每个场景检查一次输出工作簿的全部有效单元格、公式、所有差异高亮和批注坐标，并验证预览条数为 `min(5000, 总差异)`。所有检查通过。输入文件的 SHA-256 在测试前后保持一致。

另在发布版桌面界面加载大量变化样本，成功显示 9,999 处差异、5,000 条预览及搜索范围提示。界面报告的对比与导出时间为 0.63 秒（不含此前文件加载）。搜索“客户4998”正确返回 B4999 的一条差异，清除搜索后恢复全部预览。此项为功能验证，没有测量帧率或 GUI 峰值内存。

## XML 命名空间兼容性与原始文件复测

Artifact Tool 原始导出使用合法的 `x:` XML 元素前缀。`umya-spreadsheet 3.1.1` 直接匹配标签名称，无法正确读取这种写法，表现为没有工作表。初次性能测试采用了等价的默认命名空间副本，上方结果保留为初次测试记录。

现已在产品读取入口修复：使用 XML 命名空间解析器按 SpreadsheetML URI 识别标签，生成仅供读取的临时 ZIP，将这些标签适配为依赖库接受的写法。作用于工作簿、工作表、共享字符串和样式等 XML 部件。原文件只读，单元格文本、公式和属性不做字符串替换，其他命名空间及前缀重绑定按原有作用域保留。

直接使用 `dist/performance/original-export/` 中未经改写的三份 XLSX，重新执行 12 次测试。差异数量、所有变化坐标和分类、输出内容/类型/公式、高亮、批注及预览上限均核对通过，输入 SHA-256 在测试前后保持一致。

修复后的发布版桌面端也直接加载原始文件并完成对比，正确显示 9,999 处差异、5,000 条预览及完整日志提示。

| 原始文件场景 | 差异数量 | 进程总耗时中位数 | 峰值内存最大值 |
| --- | ---: | ---: | ---: |
| 完全相同 | 0 | 1.67 秒 | 377.2 MiB |
| 少量变化 | 1,200 | 1.60 秒 | 378.1 MiB |
| 大量变化 | 9,999 | 1.63 秒 | 387.0 MiB |
| 大量变化，关闭批注 | 9,999 | 1.63 秒 | 378.8 MiB |

原始文件的加载阶段包含 XML 适配开销，因此耗时高于此前预先规范化的副本。以上测量仍为同一台机器、每场景三次、未清除文件缓存。原始文件复测数据位于 `dist/performance/original-export/results.json`。

新增回归测试覆盖任意 SpreadsheetML 前缀、前缀重绑定、外部/空命名空间、文本/CDATA/公式保留，以及仅工作簿、仅其他部件、全部部件带前缀的三种实际加载场景。与原有测试合计 11 项通过。

## 重复运行

样本与完整测量结果位于 `dist/performance/`（不提交大型生成文件）。

```sh
cargo build --release --target aarch64-apple-darwin --example benchmark
python3 scripts/benchmark.py dist/performance
# 验证原始带前缀文件：
python3 scripts/benchmark.py dist/performance/original-export
```

`examples/benchmark.rs` 调用与桌面端相同的工作簿加载、配对、对比和导出代码，增加分阶段计时。`scripts/benchmark.py` 在 macOS 上使用 `/usr/bin/time -l` 测量进程耗时和最大 RSS，并写入 `dist/performance/results.json`。其他架构可以通过 `--binary` 指定对应的基准程序。
